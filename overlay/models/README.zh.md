# 统一模型设置

[English](README.md) | 中文

平台 Web profile 在**设置 → 模型**中管理模型，复用 gcs-webnora 已有的类型页签、卡片、搜索、编辑器和连接测试。其他 Harness 设置页保持原生布局。经过认证的 `/harness/models` 页面提供对话、向量、重排、视觉和语音模型，编辑权限仍由普通空间角色决定。用户在对话或各知识库中选用已配置的模型。已有文档索引保留原 Embedding 模型绑定。

## 配置与执行

`WEKNORA_BASE_URL` 指定现有、经过认证的 gcs-webnora API，包含 `/api/v1`。`WEKNORA_WEB_URL` 可另行指定浏览器访问的基础地址，包含代理子路径；不配置时从 API 地址去除 `/api/v1` 得到浏览器基础地址。Worker 提供 `DSH_PLATFORM_USER_ID`；认证使用当前用户的平台 SSO，令牌只保留在 Host 内存中。共享模型密钥或用户自行提供的身份不能替代该认证。

模型目录和凭据保留在 gcs-webnora 数据库中。Harness 通过注册的 `zhishu-models` 适配器调用经过空间授权的流式接口，由 gcs-webnora 解析凭据并访问指定的推理服务。这一层后端转发避免把已存密钥返回浏览器或用户容器，同时允许 Harness 容器停止后知识库后台任务继续运行。服务必须能在现场网络中访问。服务或模型接口不可用时，随包依赖不能代替模型推理。

模型选择使用 `<workspaceID>:<modelID>`，同名模型不会跨空间合并。准备好的请求携带已存配置版本；配置被并发修改时会明确返回配置变更错误。适配器保留工具 JSON、绑定模型的推理状态及流式用量，拒绝不完整的响应和当前后端 API 不支持的显式停止序列。图片沿用已有的保留附件投影，请求体上限为 32 MiB。

## 已有 profile

平台 overlay 禁用旧内置提供方的配置页面和路由。已有凭据不会被导入或删除。模型在统一目录中配置；空闲会话使用已退役路由时，若模型名称唯一匹配，或空间只有一个默认模型或唯一模型，就通过原生日志化模型选择 API 迁移。匹配不明确时需手动选择。正在使用的第三方适配器和已有统一模型选择保持不变。模型所有者独立于可选的知识库工具组合包加载。

## 验证

构建会运行[适配器测试](../../docker/tests/unified-models.test.mjs)及[真实 Web 组合烟测](../../docker/smoke-models.mjs)。烟测通过模拟后端认证隔离用户，迁移旧模型选择，执行知识库工具，再完成下一轮模型调用；不访问外网或真实用户存储。该测试验证组合与协议行为，现场真实模型调用需单独检查。
