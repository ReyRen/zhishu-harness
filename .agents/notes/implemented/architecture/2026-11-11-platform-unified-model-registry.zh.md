# Agent Note: 平台统一模型目录

Status: implemented

[English](2026-11-11-platform-unified-model-registry.md) | 中文

## 问题

独立的 Harness 与知识库模型编辑器要求重复配置；把凭据复制到每用户容器又会扩大访问范围，并让后台索引依赖用户运行时持续在线。

## 决策

平台“模型”分区嵌入 gcs-webnora 已有、经过认证的编辑器。其数据库持有模型定义和凭据，独立的 Harness 适配器使用当前用户 SSO 请求经过授权的推理。稳定模型 ID 包含普通空间，捕获的配置版本避免混用不同版本的元数据和凭据。共享知识库不授予其来源空间的模型配置权限。

## 考虑过的方案

在两个存储之间复制模型配置仍会存在相互竞争的所有者，并且需要复制凭据。将密钥读入 Harness 容器能减少一层推理转发，但把凭据暴露到现有所有者之外。把知识库执行迁入用户容器，会在容器停止后阻断后台工作。再做一套 React 编辑器则重复 gcs-webnora 的校验、协议目录和删除保护。

## 影响

平台推理依赖模型目录后端，并增加一层内部流式转发。认证保持每用户隔离，已存密钥保留在服务端，知识库索引独立运行。原始组合保留自己的提供方编辑器。已有平台 profile 独有的模型需要在统一目录中配置，存在歧义的旧模型选择仍由用户明确决定。适配器测试和实际 Web 组合烟测覆盖认证、退出中止、版本、模型选择、工具调用轮次和不完整流。
